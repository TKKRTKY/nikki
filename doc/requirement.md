# nikki 要件定義書

## 1. プロダクト概要

### 1.1 プロダクト名

nikki

### 1.2 コンセプト

LLMと対話しながら思考を整理し、その日の出来事や内省を「日記」という形に落とし込めるアプリケーション。

### 1.3 目的

- 日記を書く心理的・認知的ハードルを下げる
- 対話を通じて思考・感情・学びを深める
- 日々の記録を将来的な振り返りや成長に繋げる

---

## 2. 前提・基本方針

- 初期段階では **ログイン・アカウント管理を行わない**
- プロトタイプ段階のデータ保存は **IndexedDB を利用**
- IndexedDB は **プロトタイプ専用の一時的な保存手段**とする
- 将来的には以下を可能にする設計とする
  - Webアプリケーションとしての本格運用
  - 複数端末（PC / モバイル等）からのアクセス
  - サーバーを介したデータ同期
- LLMは **ユーザー自身のAPIキー（BYO API Key）** を利用
- nikkiは初期段階では日記データ・APIキーをサーバーに保存しない
- Webアプリケーション（Next.js App Router）として開発する
- 音声入力は外部ツール（Superwhisper 等）との併用を前提とする

---

## 3. 想定ユーザー

- 日記を習慣化したい個人
- 文章を書くより「話す」ほうが楽なユーザー
- LLMを内省・思考整理の補助として使いたいユーザー
- プライバシーを重視しつつ、将来的な利便性（複数端末）も求めるユーザー

---

## 4. 機能要件（全体）

### 4.1 日記作成

- 日付単位で日記を作成・保存できる
- 原則として「1日1エントリ」
- 日記本文はユーザーの言葉として保存される
- 将来的に編集・追記が可能

---

### 4.2 LLM対話

- LLMとチャット形式で会話できる
- 会話を通じて以下を支援する
  - 出来事の整理
  - 感情や考えの言語化
  - 学びや気づきの明確化
- 会話内容を元に日記本文を生成できる

---

### 4.3 音声入力

- ユーザー入力は音声入力に対応する
- 初期段階では以下を前提とする
  - Superwhisper等の外部ツールにより
  - 音声がテキストとして入力欄に流し込まれる
- nikki側での音声録音・STT処理は行わない（将来拡張）

---

### 4.4 LLM設定（BYO API Key）

- ユーザーが任意のLLM APIを設定できる
- OpenAI互換APIを基本とする
- 設定項目
  - Base URL
  - Model
  - API Key
- APIキーの保存方法
  - プロトタイプ：ローカル保存（IndexedDB）
  - 将来：暗号化・セキュアストレージを利用

---

### 4.5 データ保存・同期

#### プロトタイプ段階

- 以下のデータを **IndexedDB** に保存する
  - LLM設定
  - 日記エントリ
  - LLMとの会話ログ
- ブラウザ単位で完結し、同期は行わない
- データ容量制限は設けない（ブラウザの制限内）
- データ保存期間制限なし

#### 将来構想

- サーバーサイドに永続ストレージを持つ
- ログイン機能を導入し、ユーザー単位でデータを管理
- 複数端末から同一データへアクセス可能にする
- ローカル（IndexedDB）とサーバーの同期を行う構成も検討する

---

### 4.6 振り返り・分析（将来）

- 蓄積した日記をもとに以下を行う
  - 週次・月次の振り返り
  - 傾向分析（思考・感情・行動）
  - 次の行動や問いの提示
- プロトタイプでは実装しない

---

### 4.7 通知機能（リマインド）

- ユーザーが任意の時刻を設定できる
- 設定した時刻に以下の内容で通知を行う
  - 「日記を書く」ことを促すリマインド
- 通知から nikki を開ける導線を提供する
- ユーザーが通知を無効化できる

#### 実装方針の候補（将来）

- Web（PWA）
  - ブラウザ通知 + Service Worker
  - OS・ブラウザ制約を考慮する
- ネイティブアプリ
  - OSのローカル通知機能を利用し、安定した通知を実現

---

## 5. 非機能要件

### 5.1 セキュリティ・プライバシー

- プロトタイプでは日記データ・APIキーはサーバーに送信しない
- 将来の同期対応時には以下を考慮する
  - 通信の暗号化
  - APIキーの安全な保管
  - ユーザーごとのアクセス制御

### 5.2 可用性

- オフラインでも既存データの閲覧は可能
- LLM呼び出し失敗時も入力内容は失われない

---

## 6. データ要件（論理モデル）

### 6.1 LLM設定

- baseUrl
- model
- apiKey

### 6.2 日記エントリ

- date（YYYY-MM-DD）
- body（生成された日記本文）
- updatedAt

### 6.3 会話ログ

- role（user / assistant）
- content
- createdAt

※ 将来的にはサーバー側スキーマへ移行可能な構造を意識する

---

## 7. 画面要件（全体）

- メイン画面（今日の日記）
- 設定画面（LLM設定）
- （将来）一覧画面、振り返り画面、通知設定画面、ログイン画面

## 8. プロトタイプ（Prototype / MVP0）スコープ定義

### 8.1 プロトタイプの目的

- 「LLMと対話して日記を書く」という体験が成立するかを検証する
- 永続化・同期・認証といった複雑性を排除し、最短で触れる状態を作る

---

### 8.2 プロトタイプに **含める** 機能

#### 必須機能

1. **LLM設定（ローカル保存）**
   - Base URL / Model / API Key
   - IndexedDB に保存

2. **1日1エントリの日記作成**
   - 今日の日付で日記を作成
   - 日記本文を保存

3. **LLMチャット**
   - テキスト入力欄
   - LLM応答表示
   - 会話ログ保存

4. **会話 → 日記本文生成**
   - ボタン操作で本文生成
   - 構造化されて読みやすい形式の日記を生成
   - 生成結果を日記として保存

5. **ローカル永続化**
   - リロード後も設定・日記・会話が保持される

6. **音声入力対応（間接）**
   - テキスト入力欄を用意し、Superwhisper等で入力可能

#### 画面構成

- 単一画面（`/`）
  - LLM設定（カード形式、未設定時は目立つ表示、設定完了後は折りたたみ）
  - 2カラム構成（デスクトップ）
    - 左側：チャットUI（60%幅）
    - 右側：日記表示エリア（40%幅）
  - モバイル時：縦積み構成（上：チャット、下：日記）
  - Material DesignまたはModern UIベースのデザイン

---

### 8.3 プロトタイプに **含めない** 機能

- ログイン・ユーザー管理
- サーバーDB・データ同期
- 複数端末対応
- 日記一覧・カレンダー
- 週次・月次振り返り
- 通知機能（リマインド）
- ストリーミング応答
- 複数LLMプロバイダー切替UI
- APIキー暗号化
- アプリ内音声録音・STT
- タグ、感情分析、構造化データ

---

### 8.4 プロトタイプ完了条件（Definition of Done）

- ユーザーが以下を一連で実行できる
  1. APIキー・モデルを設定する
  2. 今日の出来事を入力する（音声 or テキスト）
  3. LLMと会話する
  4. 会話から日記本文を生成する
  5. ページを再読み込みしても内容が保持されている

---

## 9. 今後の拡張方針

- IndexedDB → サーバー永続ストレージへの移行
- ログイン機能の導入
- 複数端末同期
- 日記一覧・カレンダー表示
- draft / final 概念の導入
- 週次・月次の振り返り
- 感情・テーマの抽出と可視化
- APIキーの暗号化
- 複数LLMプロバイダー対応
- 通知機能（リマインド）
- PWA化およびネイティブアプリ展開
